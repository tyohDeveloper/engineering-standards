What Claude is, and what Claude Code adds

Learn the difference between Claude the model, the Claude apps, and Claude Code, the agent that works in a repository. Also learn why there are several model tiers.

What does Claude Code do that chatting with Claude in an app doesn't?

It works inside a repository. It reads and edits files, runs commands and tests, and delivers changes such as pull requests. A chat answers questions; Claude Code carries out the work in your codebase.

How an agent works

Understand the loop: gather context, act, check the result, repeat. Then see why context, the instructions and files the agent can see, decides the quality of the result.

  3. Effective context engineering for AI agents

    Anthropic Engineering · essay

  4. Prompt engineering overview

    Claude Platform docs

    How to write instructions Claude follows reliably. This applies to requirements, skills and subagent prompts.

    Take away: say what success looks like, give examples, and keep instructions free of contradictions.

Why would you keep your coding standards in repository files instead of repeating them in each request?

Context is limited and must be spent deliberately. Files load the same way every time, for every agent, and the agent reads them when relevant. That makes behavior consistent and checkable. Repeating standards in each request wastes context and drifts.

You want "never commit secrets" to hold without exception, and "how to write a release note" to be available when needed. Which extension does each one need?

"Never commit secrets" needs a hook, because it must hold every time and a hook runs no matter what the model decides. "How to write a release note" needs a skill, because it's a procedure loaded when relevant. Both can ship in the same plugin.

A cloud session opens a pull request. What has to happen before it's merged, and who or what does each step?

CI runs your repository's checks, Code Review comments on the change, and you approve. The agent proposes the change, automation verifies it, and you decide. Review and CI are what make agent-written code trustworthy.

When would you use opusplan instead of plain Sonnet?

When a task needs real design before coding. Opus handles the planning and Sonnet carries it out. Routine edits with no design decisions can stay on Sonnet the whole way.

A plugin passes its unit tests but the agent still ignores one rule. What kind of test catches that?

An eval, which runs the agent with the plugin installed and checks its behavior. Unit tests check the plugin's code; evals check whether the agent actually follows the rule.
