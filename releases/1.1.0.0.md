# Standards Release 1.1.0.0

Owner-approved November 7, 2026, effective upon merge of [PR #16](https://github.com/tyohDeveloper/engineering-standards/pull/16). Tag `standards-1.1.0.0` identifies the merged release revision.

## Meaning and scope

Promotes the [durable datastore concurrency classification](../standards/durable-state-model.md) from proposal to normative architectural standard. This is a substantial multi-file policy addition, represented by a second-component change from 1.0.1.1 to 1.1.0.0, not a copy correction or an authority transfer.

An architecture must identify the one or more durable datastores it uses, declare each access class, guarantee its requirements, and rely only on stated guarantees and explicit contracts. The four classes are serialized accessor, single-writer/opportunistic-readers, single-writer/multiple-readers, and multiple-writers/multiple-readers.

Serialized accessor grants zero or one active accessor exclusive access to the entire datastore until release, potentially across multiple operations and idle periods. Ordinary-operation atomicity, where declared, is an observable guarantee; lock granularity and provider mechanisms are implementation choices. Opportunistic reads may return indeterminate, incomplete, or mixed old/new state without atomicity, consistency, completeness, or stable-view guarantees and do not exclude other access.

Durable has device, hosted, and reserved shared subclasses. Ownership, the browser-local single-owner serialized-accessor binding, and application/system processing coordination are supporting architectural clarifications; only illustrations are non-normative. Browser-local hierarchy placement remains open.

The release also updates navigation, connects the classification to delivery profiles and architecture review, and records the manual enforcement mapping. It does not change profile enums, validator/schema values, reserved-value status, source snapshots, application repositories, or application adoption pins.

## Verification and enforcement

`npm run validate` and all 14 tests in `npm test` passed under Node 22.23.4 for the promotion change. These verify repository integrity, source hashes, Markdown links, and adoption metadata; they do not certify datastore behavior or application compliance. A direct comparison also confirmed that the four-class definitions and concurrency guarantees are unchanged from the reviewed pre-promotion head.

Architectural conformance is explicitly human-reviewed through the [architecture review](../reviews/architecture-review.md), using the standard's synthetic cases and obligation-by-obligation enforcement mapping. This release does not claim an executable semantic checker or completed application audit.

## Adoption effects

Existing application pins continue to identify their previously adopted releases. Applications adopt 1.1.0.0 deliberately through the [existing adoption process](../adoption/README.md), pinning the release and immutable source commit and recording their datastore declarations and verification evidence.

The architectural declaration is required for adopters even though no new machine-readable manifest field is introduced here. Access duration, operation boundaries, and consistency/conflict-resolution contracts are declared where required by the selected class; provider-specific implementation choices remain with the application/system.
