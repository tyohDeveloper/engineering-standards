# Hub Checkpoint 0.1.0.0

Date: 2026-10-09. Status: initial scaffold; not a new normative policy release.

## Meaning

Establish a maintained engineering standards surface with provenance, governance, reviews, templates, and integrity checks. The existing v2.2 policy remains separately identified and retains its stated authority pending migration review.

## Scope

- Private GitHub hub and Engineering Standards Project.
- Two immutable application-source snapshots with licenses and SHA-256 hashes.
- Shared architecture/coding orientation without transplanting application mappings.
- Authority, versioning, review, exception, and adoption templates.
- Dependency-free hub validation and pinned GitHub Actions.

## Verification and limitations

`npm run validate` checks required files, Markdown paths, source hashes, version labels, adoption metadata, and basic governance guardrails. It does not audit application code or certify normative migration.

Application target profiles and the companion wiki pages remain to be reconciled. No application adoption, application release, data release, or authority-transfer tag is created.

## Project snapshots

Project Files are a manual snapshot of an exact GitHub commit, with `SOURCE-SYNC.json` recording lineage. Future upstream edits do not automatically propagate.
