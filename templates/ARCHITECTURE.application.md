# Application Architecture

## Adopted standards and scope

Record the policy version, immutable source, application commit, targets, and owner.

## Responsibilities and role/path mapping

Map VIEW, CONTROLLER, STATE, PURE, PURE-CORE, DATA, and any applicable PLATFORM-PURE, PLATFORM-AMBIENT, MODEL, or REMOTE roles to actual responsibility-named paths. An unmapped role is explicit, not guessed.

## Boundaries

Describe dependency direction, data flow, effect sequencing, state ownership, persistent write/migration authority, and cross-service contracts.

## Contracts

Document build artifacts, data/schema validation, localization, security boundaries, mandated binding authority, and target-specific profiles where applicable.

## Decisions and checks

Link numbered ADRs, rejected alternatives, automated checks, manual review obligations, and approved exceptions.
